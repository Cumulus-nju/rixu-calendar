# 日序 · 多设备同步设置

日序默认只把日程存在本机。想让**家里电脑和办公室电脑**用同一份日历，可以接一个
免费的 Supabase 项目：登录一次，日程、来源、模板、周期定义和偏好设置会自动同步。

> 只同步日程、来源、模板、周期定义和偏好设置。**API Key 和 NapCat Token 永远不上传**；
> 「开机自启 / 关窗驻留」这类单机设置也不会同步到别的电脑。

---

## 一、建一个 Supabase 项目（约 5 分钟，只做一次）

1. 打开 <https://supabase.com/>，用 GitHub 或邮箱注册，点 **New project**。
   - 名字随意，例如 `rixu`；
   - Region 选 **Southeast Asia (Singapore)** 或离你最近的；
   - 数据库密码随便设一个，**记不记都行**——日序不用它，用的是下面两个公开值。

2. 等 1–2 分钟项目创建完，进入 **SQL Editor**，把仓库里
   [`supabase/schema.sql`](../supabase/schema.sql) 的整段内容粘进去，点 **Run**。
   成功后 `rixu_items` 表就建好了，并且开启了按用户隔离的 RLS。
   已经在用旧版表结构的项目，重跑一次本文件即可补上模板 / 周期的 `kind` 约束。

3. 打开 **Project Settings → API**，记下两个值：

   | 名称 | 长什么样 | 说明 |
   |---|---|---|
   | Project URL | `https://abcd1234.supabase.co` | 填到日序的「Supabase 地址」 |
   | anon public key | `eyJhbGciOi...` 很长一串 | 填到日序的「anon key」 |

   ⚠️ 不要用 `service_role` 那个密钥，它绕过 RLS，泄露等于把整库交出去。
   `anon public` 本来就是给客户端用的公开密钥，安全性由 RLS 保证。

4.（可选）不想每次注册都去邮箱点确认链接：
   **Authentication → Providers → Email**，把 **Confirm email** 关掉。

---

## 二、第一台电脑：注册并同步

1. 打开日序 → **设置 → 账号与同步**，填 Project URL 和 anon key，点 **保存并连接**。
2. 填邮箱和密码（至少 6 位），点 **注册新账号**。
   - 如果开了邮箱确认，会提示你去邮箱点确认链接；点完回来点 **登录**。
   - 注册成功会自动把本机已有的日程推上云。
3. 之后日序每 60 秒、以及每次本地改动后约 8 秒，都会自动同步一次；
   也可以随时点 **立即同步**。

## 三、第二台电脑：登录，不要注册

1. 装好日序，同样填**同一个** Project URL 和 anon key。
2. 用**同一个邮箱密码点「登录」**（不是注册）。
3. 登录成功后会先把云端的日程拉下来，再继续双向同步。

---

## 四、它怎么合并

- 每条日程、来源、模板、周期定义、设置是一个独立条目，按 `kind:id` 对齐。
- 两台电脑改的不是同一条：互不影响，各推各的。
- 两台电脑改了同一条：后改的赢（按条目最后更新时间，Last-Writer-Wins）。
- 在一台删掉的条目：会推一条墓碑记录，另一台下次同步也会删掉；90 天后墓碑自动清理。
- 新设备第一次同步只拉不删：不会因为你刚装好、本地还是空的，就把云端的日程清空。

## 五、常见问题

**「数据库里还没有 rixu_items 表」**
`supabase/schema.sql` 没执行，或执行到了别的项目里。

**「没有权限 / row-level security」**
同一个项目的 RLS 策略没建好。重新执行一遍 `schema.sql` 里的 `create policy` 部分。

**「邮箱还没验证」**
去邮箱点确认链接；或在 Supabase 里关掉 Confirm email。

**换账号了会怎样**
日序检测到 `user_id` 变了，会清掉本地同步游标，按新账号重新拉取；本机已有的日程会
作为「本地新增」推给新账号。如果不想混在一起，先退出登录再换号。

**数据在谁的服务器上**
在你自己的 Supabase 项目里，日序没有中转服务器。免费额度对个人日历绰绰有余。

## 六、开发者备注

- 表结构：`user_id, kind, id, payload(jsonb), updated_at, deleted`，主键 `(user_id, kind, id)`。
- 客户端只用 Auth 的密码登录和 PostgREST 的 `GET/POST`，代码在
  `src/sync-net.js`、`src/sync-engine.js`。
- 同步状态写在 `%APPDATA%\rixu-calendar\sync-state.json`：只含指纹、时间游标和
  加密后的 token（Electron `safeStorage`），不含日程正文。
- 断网、没登录都不影响本地使用，同步只是叠加在上面的一层。
