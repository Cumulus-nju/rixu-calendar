# 日序 · 同步文件夹（OneDrive / 坚果云）

日序默认只把日程存在本机。如果你想让**家里电脑和办公室电脑**用同一份日历，
又不想注册账号、不想建服务器，可以用「同步文件夹」：

> 把日历写成一个 `rixu-sync.json`，放进你的 OneDrive / 坚果云同步文件夹。
> 两台电脑都指向同一个文件夹，云盘负责把文件传过去，日序负责合并内容。

零账号、零服务器；文件夹里是什么，云盘服务商就能看到什么，但 **API Key 和
NapCat Token 永远不会写进去**。

---

## 一、第一台电脑：选一个同步文件夹

1. 打开日序 → **设置 → 同步文件夹**。
2. 如果检测到 OneDrive / 坚果云，会直接给出按钮；没有就点 **选择文件夹…**。
3. 建议在同步盘里单独建一个「日序」文件夹，例如：
   - `C:\Users\你\OneDrive\日序`
   - `C:\Users\你\Nutstore\我的坚果云\日序`
4. 选好后，日序会生成 `rixu-sync.json`，并立即把本机日程写进去。

文件夹路径只记在这台电脑上，不会跟着文件同步到另一台电脑（两台电脑的路径可以不一样）。

## 二、第二台电脑：指向同一个文件夹

1. 确认第二台电脑的 OneDrive / 坚果云客户端已经把那个文件夹同步到本地。
2. 打开日序 → **设置 → 同步文件夹**，选到同一个文件夹。
3. 日序发现文件夹里已经有日历，会问 **「加入已有日历？」**。
4. 确认后，云端日程会拉下来，本机已有的日程也会合并进去。

> 如果这个文件夹不是你的，点取消，换一个空文件夹。

## 三、之后怎么同步

- 日序每 **30 秒**检查一次同步文件夹；
- 本机改动保存后约 **5 秒**会写一次；
- 设置里也可以随时点 **立即同步**。

同步是「快照合并」，不是实时推送；云盘客户端本身也有几秒到几十秒的延迟。
刚在另一台电脑改完，这边一般等云盘同步完就会看到。

## 四、它同步什么

会同步：

- 日程（含周期日程展开后的每一次）
- 来源（群 / 好友的重要性标记）
- 待确认
- 快捷导入模板、周期定义
- 偏好设置（通知、自动加入阈值、AI 开关等）

**不会同步**（也不该同步）：

- `settings.llm.apiKey`
- `settings.napcat.token`
- 「开机自启 / 关窗驻留」这类单机设置
- 本机的采集开关状态会同步偏好，但每台电脑实际是否监听剪贴板以本机设置为准

## 五、冲突怎么处理

日序按条目（`kind:id`）合并，规则和 Supabase 同步一致：

- 两台电脑改的是不同条目：都保留。
- 两台电脑改同一条：更新时间较新的赢（Last-Writer-Wins）。
- 删除会写一条「墓碑」，另一台下次同步也会删掉；90 天后墓碑清理。
- 新设备第一次同步不会删除已有数据：不会因为本机是空的，就把云端的日程清空。

云盘自己也可能生成冲突副本，例如：

```text
rixu-sync-DESKTOP-ABC.json
rixu-sync (1).json
rixu-sync (冲突).json
```

日序会把这些副本一起合并，然后改名为 `*.json.merged` 保留。
**不要手动删除这些 `.merged` 文件**，它们只是备份；合并后的内容已经在主文件里。

## 六、常见问题

**文件夹里没有 `rixu-sync.json`**

第一次同步还没完成，或文件夹没有写权限。看设置里的错误提示；确认文件夹不是只读的。

**另一台电脑看不到新日程**

先确认云盘客户端已经把 `rixu-sync.json` 同步到本地。可以在文件资源管理器里看修改时间；
然后在日序里点「立即同步」。

**提示「加入已有日历」**

这是正常的，说明这个文件夹里已经有一份日历。确认是你自己的另一台电脑，再点加入。

**提示「文件夹里有多个不同的日序日历」**

同一个文件夹里混了两套快照。把不属于这套日历的 `rixu-sync*.json` 移走，只留一套。

**OneDrive 显示「按需下载」/ 云端文件**

日序需要读到本地文件。第一次打开文件夹时让 OneDrive 把 `rixu-sync.json` 下载下来，
或把「日序」文件夹设为「始终保留在此设备上」。

**换电脑 / 重装系统**

重新选到同一个同步文件夹即可；如果提示加入已有日历，确认加入。

**想停用**

设置 → 同步文件夹 → **停用**。本机日程不受影响，文件夹里的 `rixu-sync.json` 也不会被删。
重新启用时选回同一个文件夹即可。

**两个人能共用吗**

不建议。一个文件夹只放一套日历。共用会互相合并对方的日程；要共用请用 Supabase 的多用户方案
（目前没有做团队共享）。

## 七、安全与隐私

- 同步文件是**明文 JSON**，里面是日程标题、时间、地点、备注、来源名和偏好设置。
- 它放在你自己的云盘里，云盘服务商能像看其他文件一样看到它。
- API Key / NapCat Token 不在文件里；这两项只存在本机。
- 日序没有中转服务器，也不会上传到你不知道的地方。
- 文件夹路径只存在本机的 `folder-sync-state.json`，不同步。

## 八、开发者备注

- 快照文件名：`rixu-sync.json`；结构：`{ app, schema, calendarId, device, updatedAt, items }`。
- `items` 的键是 `kind:id`，值是 `{ kind, id, payload, updated_at, deleted }`。
- 读取时会把同目录下所有 `rixu-sync*.json`（排除 `.merged`）合并；同一键取较新的 `updated_at`。
- 合并 / 差异 / 墓碑复用 `src/sync-core.js`；文件读写和冲突副本处理在
  `src/folder-sync-engine.js`；纯合并逻辑在 `src/folder-sync-core.js`。
- 本机状态写在 `%APPDATA%\rixu-calendar\folder-sync-state.json`，只含路径、指纹、
  时间游标和墓碑，不含日程正文。
- 与 Supabase 同步**二选一**：启用同步文件夹时，Supabase 自动同步暂停；登录 Supabase 时，
  同步文件夹的启用会被拒绝。
